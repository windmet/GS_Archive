## 仍缺失的服务字段

本轮没有伪造 `GashaListReply` 中未留存的实例值。以下内容仍然需要服务响应、其他设备缓存或可靠外部档案：

- 单抽、十连和票券消耗；
- 稀有度与 Pickup 概率；
- 保底、交换、阶梯进度和免费次数；
- 完整卡池库存，尤其是非同期新卡；
- 卡池说明、注意事项与运营标签。

## 下一步建议

1. 建立独立的 `gasha_pool_evidence` 整理层，区分“同期新卡”“复刻继承”“完整库存”和“仅横幅展示”。
2. 从 IPA 的 UI Prefab、SpriteAtlas 和本地化资源整理卡池按钮、货币、标签与弹窗组件，为整体 UI 重构提供真实资产字典。
3. 对照 IL2CPP protobuf schema，为缺失的服务字段建立 nullable 数据模型；没有实例证据时显示 `unknown`，不反推概率和价格。
4. 将卡池、卡片、活动、卡片小剧情继续保持独立实体，只通过有证据的关系表互相导航。
