# 卡面详情媒体交互 - 2026-07-13

## 本轮目标

在不改变卡片数据模型和稳定 URL 的前提下，让卡片详情具备资料库应有的连续浏览与原图检查能力。

## 已实现

- 普通、特训后和单卡面图片均可打开全屏原图。
- 大图查看器支持关闭、上一张、下一张、方向键、Esc，以及“适应窗口 / 原始尺寸”切换。
- SSR 横图与 portrait 卡面共用同一个媒体序列。
- portrait 可在“无框 / 带框”之间切换，偏好记录在 `sidem-archive-card-art-mode`。
- 详情页加入当前偶像卡片序列的上一张/下一张按钮；切换后更新 `card` URL，可刷新、分享和使用浏览器历史。
- 第一张和最后一张不循环，避免用户在长卡片序列中失去位置感。

## 卡面尺寸结论

`image_card_portrait_hide_*` 与 `image_card_portrait_show_*` 的实际尺寸是 `640 x 800`，原生比例为 `4:5`。

早期预览容器错误使用 `8:11` 与 `object-fit: cover`，会裁掉带框图左右两侧，尤其影响稀有度标识、签名和姓名框。详情预览现统一使用：

```css
aspect-ratio: 4 / 5;
object-fit: contain;
```

“无框 / 带框”只切换资源文件，不再改变布局尺寸，因此切换时不会造成详情头部跳动。

## 数据和组件边界

- `CardAssetResolver.js` 继续只负责外部资源 URL。
- `ArchiveCardDetail.vue` 负责媒体列表、显示模式和卡间导航控件。
- `ArchiveImageLightbox.vue` 是可复用的全屏媒体查看器，不读取卡片 masterdata。
- `App.vue` 负责当前偶像卡序、稳定路由和显示偏好持久化。
- `archive_manifest.json` 仍是资源存在性来源；本轮不引入新的猜测字段。

## 下一阶段建议

1. 把同一媒体查看器接到卡片目录网格的快速预览，但保留点击卡片主体进入详情的默认行为。
2. 为卡片详情增加可追溯的系列/活动关联；不要仅依靠标题字符串归组。
3. 建立统一的资料页设置入口，集中管理卡面模式、列表密度和后续语言选项。
4. 将 `App.vue` 中卡片路由协调逻辑提取为 archive navigation composable，继续缩小入口组件。
5. 在静态部署方案确定后，再处理外部卡图根目录配置、缓存版本和缺图占位策略。
