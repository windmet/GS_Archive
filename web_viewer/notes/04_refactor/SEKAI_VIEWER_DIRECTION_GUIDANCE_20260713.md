# 参考 Sekai Viewer 的 SideM 资料库重构方向 - 2026-07-13

## 决策

正式选择方案 A：将当前项目建设为 SideM 资料库与剧情回放器，不复刻完整游戏主界面或账号/玩法系统。

参考项目：

- 源码：[Sekai-World/sekai-viewer](https://github.com/Sekai-World/sekai-viewer)
- 线上站点：[sekai.best](https://sekai.best/)

我们复刻的是资料产品的组织方式，不复制 Project Sekai 的品牌皮肤，也不直接搬运 React/MUI 实现。参考仓库采用 GPL-3.0；除非项目明确接受对应许可证义务，否则只借鉴公开可观察的信息架构和交互模式，并在现有 Vue 代码中独立实现。

## 参考项目的有效模式

### 1. 稳定的资料应用外壳

Sekai Viewer 使用持久侧栏按“社区、信息、工具、关于”等资料域分组，顶部只承担折叠、返回、设置和账户等全局操作。内容页始终位于同一个可滚动容器中，移动端改为抽屉导航。

SideM 对应实现：

- 首页、故事、偶像、卡片、互动与资源共用 `ArchiveShell`。
- 桌面使用持久侧栏；移动端使用固定底部主导航。这里不机械照搬抽屉，而是保留五个高频资料域的一步切换。
- `StoryViewer` 和 `SpineViewer` 保持全屏工具边界，不塞进资料页滚动容器。

### 2. 列表页是查询工具，不是展示墙

卡片页同时提供搜索、多维筛选、排序和多种视图，并把筛选偏好持久化。列表使用渐进加载，卡片本身只显示识别所需的信息。

SideM 第一阶段对应：

- 卡片：偶像、稀有度、关键词、觉醒状态和资源可用性。
- 故事：类型、偶像/组合、资源 ID、标题和可播放状态。
- 偶像：组合、姓名和拥有的卡片/故事数量。
- 首先保留 URL 可分享筛选；个人显示偏好再使用 localStorage。

### 3. 详情页围绕一个稳定资源 ID

Sekai Viewer 的卡片、角色、活动等详情都使用独立 URL，并在详情内组合图片、属性、关联内容、音频与资源入口。

SideM 对应：

- 卡片详情继续使用 `card` 资源 ID，展示觉醒前后、首页语音、关联剧情和资源状态，并支持连续卡片浏览与原图检查。
- 偶像详情以 `idol_code` 为稳定 ID，聚合档案、组合、卡片、个人故事和通讯。
- 故事条目以 compiled file/resource ID 为稳定入口，播放器返回原筛选状态。

### 4. 剧情回放是资料域中的独立工具

Sekai Viewer 将剧情先按 event/unit/chara/card/area/special 等类别选择，再交给 reader 展示；选择器和阅读器互相独立。

SideM 已经具备更强的舞台播放器，因此只借鉴选择流程：

```text
故事资料页
  -> 类型
  -> 组合/偶像/活动
  -> 章节/文件
  -> StoryViewer
```

`StoryViewer` 继续读取 compiled scenario；masterdata 只负责标题、分类与关联，不参与猜测镜头和动作。

### 5. 数据版本和可用性是正式 UI 信息

Sekai Viewer 首页明确展示客户端、数据和资产版本。SideM 当前没有统一版本号，但可以展示生成时间、索引条目数和资源覆盖率。

建议新增 `archive_manifest.json`：

- `generated_at`
- `compiled_scenario_count`
- `card_count`
- `idol_count`
- `background_count`
- `spine_model_count`
- 各资料域可播放/仅 masterdata/缺少资源数量

## 不照搬的部分

- 不迁移 React、MUI、MobX 或其组件源码；现有 Vue/Pixi 技术栈足够。
- 不接入账户、社区、公告、活动倒计时、扭蛋模拟器或游戏进度。
- 不为了与参考站一致而引入后端数据库。当前内容以静态索引和本地资源读取更合适。
- 不照抄深色主题；视觉应保留 SideM 的青绿识别色、清晰图片和更适合剧情资料的密度。
- 不用 masterdata 中尚未确认的数字字段制造看似完整的属性面板。

## 实施顺序

### P1：统一资料外壳

1. 移除 `GameHomeStage` 方向性原型和 `homeIdol` 路由字段。
2. `ArchiveShell` 包裹首页、故事、偶像、卡片和通讯目录。
3. 统一页面标题、返回、搜索、侧栏激活状态与移动端导航。
4. 播放器和 Spine 实验室继续全屏显示。

### P2：建立资料域首页与筛选

1. 首页显示资料域快捷入口和真实索引统计。
2. 故事页统一分类、搜索和可播放状态。
3. 卡片页增加网格/紧凑列表切换，并保留稀有度与关键词筛选。
4. 偶像页增加组合筛选并建立独立详情页。

### P3：详情关联与资源工具

1. 偶像详情聚合卡片、个人剧情、聊天和电话。
2. 卡片详情补齐觉醒前后图片、语音与关联剧情状态。
3. 新增资源目录入口，逐步公开背景、音乐、Spine 和素材可用性。
4. 生成统一 `archive_manifest.json` 并在首页展示数据版本信息。

## 第一版完成标准

- 所有资料页共享同一外壳，桌面和移动端导航一致。
- 每个主要资源均有可刷新、可分享的稳定 URL。
- 故事、偶像和卡片至少各有搜索/筛选与独立详情入口。
- 播放器能从资料页进入并返回原来的筛选位置。
- UI 只展示有权威来源的数据，并明确缺失或不可播放状态。
- 构建、桌面与移动端核心流程回归通过。
