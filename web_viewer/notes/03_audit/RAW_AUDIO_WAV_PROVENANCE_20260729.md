## Conclusion

The 18 WAV files observed under `RAW/audio` were reproducible decoded
derivatives, not authoritative RAW inputs:

- 17 files are exact PCM decodes of selections 1–17 from
  `song3_drvalv.acb`;
- one file is the exact PCM decode of selection 1 from
  `song3_drv999.acb`;
- all 18 decoded byte streams match their mounted WAV files byte-for-byte;
- their names are vgmstream's default output pattern:
  `<input>.wav` and `<input>#<selection>.wav`;
- they were generated by the live-chibi audio source regression because
  metadata inspection used `vgmstream -I` without `-m`.

The source defect is fixed by `eb44640 fix: keep live audio inspection out of
RAW`. All 18 derived files have now been moved without deletion into an ignored,
recoverable quarantine subdirectory. The recorded RAW baseline was not changed.

## Root cause

`scripts/prepare-live-chibi-audio.py` first inspects every ACB selection before
choosing the stream to transcode. Before `eb44640`, it invoked:

```text
vgmstream-cli -I <ACB>
vgmstream-cli -s <selection> -I <ACB>
```

In the configured vgmstream build, `-I` requests JSON information but does not
disable decoding. Without `-m`, the CLI also writes its default output beside
the input. For a multi-stream ACB this produces the exact names seen here.

The corrected commands are:

```text
vgmstream-cli -m -I <ACB>
vgmstream-cli -m -s <selection> -I <ACB>
```

The new `verify:live-chibi-audio` gate checks every metadata command for `-m`
and rejects output or pipe flags. A live `-m -I` check also left the existing
WAV modification time unchanged.

the modification time changed. No other WAV received a newer modification
time. At disclosure time the file had not been moved; it was subsequently
included in the authorized quarantine operation below.
