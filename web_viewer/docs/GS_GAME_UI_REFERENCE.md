# 游戏 UI 信息构成参考

取材：用户提供的游戏截图，放在本地 `.analysis/game-ui-reference/`（`通信`、`阅读器`、`主页`、`其他`），不进 Git。
用法：借鉴**信息怎么组织**，不照搬外框。游戏界面框线多、饱和色块大；资料馆仍按「节目册」方向（纸面、细线、少框，见 `GS_UI_CONSTITUTION.md`），只吸收下面的结构规律。

## 1. 每个场景只有一个「主人」

- **电话**：手机屏上半是主人的通话背景（信物照片），正中是主人的圆头像，下面一枚藏青名牌，台词框放在下半的浅色区。整通电话里头像和名牌不变；别人插话（例：牙崎涟【薄闇が包む退屈】获得电话里的春名、雨彦）也只体现在台词上。
- **聊天**：顶栏写房间名（个人聊天写偶像名，组合聊天写组合名），顶栏和底纹用这个房间的颜色或图案（Beit 是青色和雪花，涟是深灰和爪痕）。每条消息自带头像和名字，房间不随说话人变化。
- **资料馆对应**：通信的房间归属从场景编号读出（`communicationOwnerId`），说话人只决定这一句的标签。门户可以额外注明「这通电话里还有谁」，游戏里没有这一信息。

## 2. 名字永远贴着文字

- ADV 和主页台词都是同一种结构：绿色名牌压在台词框的左上沿，名牌在前，文字在后。
- 资料馆偶像主页的绿色名牌已经是这个结构；通话里的插话者用台词框内的小字名签，因为名牌位置留给房间主人。

## 3. 列表 = 头像 + 名字 + 状态

- 通信的偶像列表：圆头像、全名，右侧一个蓝色未读圆点，没有其他装饰。
- 分组切换（アイドル / ユニット）放在列表外侧，选中项用实色块加指向箭头。
- **资料馆对应**：列表行先给识别（头像或缩略图加名称），再给一个状态，次要信息往后放或收起。

## 4. 结果和资料用「标签 + 数值」成组

- WORK RESULT 分成 PRODUCER / IDOL / REWARD 三段，每段一条带左侧短竖线的标题栏。段内是灰底小标签（「プロデューサーLv」「信頼度」「ファン数」）加大号数值，增量用小胶囊（`+105`）。
- **资料馆对应**：分节标题加细线（`story-section-head` 已是），数据写成「标签 · 数值」，增量和状态用小胶囊，不另开卡片。

## 5. 标题是「日文名 + 英文副标」成对出现

- 主菜单每项都是图标、日文主标题、灰色英文副标（ユニット編成 / UNIT、ピクチャースタジオ / PICTURE STUDIO）。
- 页面标题左侧一条绿色短竖线（お仕事、トーク）。
- **资料馆对应**：中文主标题即可。英文眉标此前已决定不用；短竖线可以作为页内分节的唯一装饰。

## 6. 属性色

- Physical 红、Intelligence 青、Mental 黄、All 绿，在游戏里都是饱和色块加图标。
- **资料馆对应**：目录里只铺一层浅底色（2026-10-06 已改），饱和色只留给需要立即分辨的地方（属性筛选的选中态、详情页的属性标）。

## 7. 宽屏构图

- 通信、聊天、主菜单在横屏上都是「一块竖向主体 + 一侧操作」：手机屏偏左居中，选项气泡放在手机外的右侧；主菜单左边一列竖向横幅，右边一块功能网格。
- **资料馆对应**：电脑版通信页用左侧通话卡（主人和信物）加右侧内容列表，对应这个构图。左卡跟随滚动保持可见，右侧承担全部信息，避免左栏下方大片空白。
