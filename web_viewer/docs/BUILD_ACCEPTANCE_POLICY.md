# 构建、验收、提交与磁盘约束

2026-09-12，针对C盘重复构建副本事故制定。适用于所有模型与窗口，不依赖先前对话记忆。

## 日常代码验收

使用 `npm run build:check`。它仍执行完整Vite生产代码编译、打包和chunk检查，但设置 `copyPublicDir:false`，不复制 `public/assets`、compiled、reading、translations等静态语料。输出固定在当前工程 `.analysis/build-check`，每次只替换这个可重建目录，不创建按批次累积的构建副本。

这不是增量编译或跳过代码检查；它也不是完整可独立部署包。Browser通常使用已核实归属的本工程dev服务，直接读取已有public与配置资源。若验证生产bundle，必须使用明确的静态资源映射服务并记录路径/版本，不能把缺资源的build-check直接当发布产物。开发服务验收与生产bundle验收分别标注。

不要每次提交执行 `npm run build` / `npm run smoke` / 默认 `vite build --outDir ...`：当前默认Vite会复制public全库，即使outDir在仓库外也一样。历史快速验收使用的是Vite API加copyPublicDir:false，而不是省略生产代码编译。现有build/smoke保留原打包语义，避免悄悄改变发布调用方；日常一律用新增build:check。

## 按变更选择验证

| 改动 | 必需验收 | 构建要求 |
| --- | --- | --- |
| 纯文档/工作记录 | 核对事实、链接、状态边界、git diff --check | 不构建 |
| 纯状态/数据/工具逻辑 | 对应合同及行为回归；检查真实受影响来源 | 前端依赖受影响时build:check；纯Python/独立工具不机械跑Vite |
| Vue/前端接线/样式 | 对应回归、build:check、真实Browser目标旅程 | 一次代码构建；新改动/失败才重跑相关项 |
| 资源路径/预载/媒体能力 | 计划与消费者一致性、真实资源/HTTP/播放验证 | build:check不能替代真实资源检查 |
| 实际部署/资源打包 | 完整package清单、资源映射与目标环境验收 | 仅此时执行全量public打包 |

不能用测试数量或构建次数代替需求覆盖。既有必须运行的CI门禁仍执行；本规则只避免无必要的全库搬运。构建通过不等于Browser通过，更不等于长音频/长稳验收。

## 全量打包的前置条件

先说明要验证的发布/资源问题，统计public源与输出大小，检查磁盘可用空间及在用服务。输出使用E盘本工程明确的可重建发布目录，禁止写入C盘、系统Temp或Codex QA目录。至少预留预计副本大小之外10GiB空间；涉及旧包并存时按峰值计算。不要把相同全库按每个提交复制一次。

只保留确有用途的当前包及必要对照；保留日志、截图、fixture、来源摘要等小型证据。全量包即使复制成功，也不能保证dev middleware所服务的外部音频等都已包含，仍须按实际发布合同验收。

## 清理与提交

1. 核对当前HEAD、分支、worktree与工作区，辨别其他窗口新增工作；不覆盖、不回退已有提交。
2. 清理前解析绝对路径，确认在指定QA/构建根内、无重解析链接、不属于源码/原始资源，检查进程是否使用。只删确认可重建的build子目录，保留截图/日志/fixture及无关文件。Windows全程使用同一种文件操作方式，禁止跨shell拼接删除。
3. 执行范围相关回归，再按上表决定代码构建与Browser验收。复用已在运行且归属正确的服务，不随意关闭5173/5175或其他项目进程。
4. 文档记录输入HEAD、改动、命令结果、Browser实际旅程、产物目录/是否含public、已知限制。不把完整源码编译写成完整媒体发布包。
5. `git diff --check`后显式stage相关路径，分批commit/push；不默认PR/部署。构建产物不提交；无关v9 HTML保持原状。

事故占用与回收实测见工作交接的对应记录。后续若仍增长，先核对构建命令和输出内容，再调查其他C盘来源；不要未经定位广泛清空用户缓存。
