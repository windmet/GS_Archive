# 翻译工程（骨架）

**论点**：译文绑在原文上，不绑在位置上；原文没变，译文就不会丢，原文改了就会被发现。

## 事实

- 两条流程〔`GS_ARCHIVE_GENERAL_TRANSLATION_WORKFLOW.md`，10-15〕：
  - 剧情正文（含季节企划）走剧情 Studio 批次，按 Reader 文本单元 `unit_id + source_hash` 绑定。
  - 一句对一句的通用文本（资料名称、卡面台词、触摸语音、电话标题、通信聊天）走翻译记忆：键是原文的 SHA-256，使用位置只是上下文。
    原文改了就变成新键，旧条目留着但不发布。
- 文本身份补账（9-29）：Reader 30,121 条非空文本行全部有稳定身份。〔`GS_STORY_TEXT_IDENTITY_CLOSEOUT_20260929.md`〕
- 称呼基准：B001 已校对，作为称呼的参照。〔`TRANSLATION_B001_REVIEW_20260929.md`〕
- 规模（10-30 口径）：Reader 32,760 条有译文；通信聊天 12 批 11,534 条在 draft，已逐句复验，但 draft 不等于 reviewed。〔`CURRENT_STATE.md` 翻译一行；`TRANSLATION_CHATS_ACCEPTANCE_20261031.md`〕
- 译文 release 绑定到已提交、已部署的翻译包字节。〔PR #167，11-03〕
- 工具：Gemini（AI Studio）初翻，GPT、后来是 Claude 审查。〔站长自述，C 级〕
